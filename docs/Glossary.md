# Glossary

| Term | Definition |
|---|---|
| Baseline | Approved reference point used to measure subsequent change in scope, schedule, cost, configuration, or performance. |
| Benefit realization | Verified conversion of an approved opportunity into measurable business value. |
| Change failure rate | Percentage of production changes that cause rollback, incident, degradation, or corrective remediation. |
| Configuration object | Jira artifact such as a workflow, scheme, field, screen, permission, notification, issue type, or automation rule. |
| Configuration rationalization | Controlled removal, consolidation, or redesign of redundant and weakly governed configuration. |
| Cutover | Coordinated transition from the current operating state to the approved target state. |
| Cycle time | Elapsed time from active work start to completion, based on governed workflow events. |
| Data lineage | Traceable path from source record through extraction, transformation, model, measure, and published output. |
| Decision latency | Time between a decision request or escalation and a recorded, actionable decision. |
| Dependency | A relationship where delivery, readiness, or operation of one item relies on another party, system, decision, or event. |
| DORA metrics | Deployment frequency, lead time for change, change failure rate, and time to restore service. |
| Drill-through | Navigation from a summarized indicator to the detailed records or lower-grain analysis supporting it. |
| FinOps | Collaborative practices that improve accountability and value management for cloud and technology spending. |
| Grain | The precise meaning of one row in a data table. |
| Hypercare | Time-bound period of enhanced monitoring, support, and defect resolution after implementation or cutover. |
| Idempotency | Property that allows the same operation to be safely repeated without creating unintended duplicate effects. |
| Issue snapshot | Recorded state of an issue at a defined point in time, used for historical reporting. |
| JQL | Jira Query Language used to select issues matching defined conditions. |
| KPI | Governed key performance indicator connected to a decision, owner, target, formula, and validation method. |
| Lead time for change | Elapsed time from an approved or committed change to successful production deployment. |
| Mandatory-field completeness | Percentage of eligible records containing valid values for required reporting or process fields. |
| Migration wave | Controlled group of objects, projects, teams, or data moved together according to an approved sequence. |
| Operating model | Defined combination of roles, decision rights, processes, governance, technology, and measures used to deliver outcomes. |
| Plan reliability | Completed planned scope divided by approved committed scope for the period. |
| Portfolio health | Governed assessment of schedule, scope, cost, benefit, risk, quality, and dependency conditions across initiatives. |
| RAG | Green, amber, red, and where required unavailable states calculated from approved thresholds and evidence. |
| Reconciliation | Comparison of data and measures between source and target to confirm completeness and accuracy. |
| Recovery point objective | Maximum acceptable amount of data loss measured in time. |
| Recovery time objective | Maximum acceptable time to restore a service or capability after disruption. |
| Rollover | Work not completed in the planned sprint and moved or carried into a later sprint. |
| Row-level security | Data-model control that restricts records visible to a user based on approved access rules. |
| Scope stability | Measure of how much committed scope remained unchanged during a delivery period. |
| Semantic model | Governed analytical layer containing relationships, dimensions, facts, measures, metadata, and security. |
| Service identity | Non-personal account used by an approved application, integration, or reporting process. |
| SLA | Service-level agreement or objective measured using an approved calendar, start, pause, stop, and success definition. |
| Sprint commitment | Approved work included at the governed sprint commitment point. |
| Synthetic data | Artificially generated data that represents realistic patterns without exposing actual organizational information. |
| Technical debt | Future cost or risk created by expedient design, configuration, code, process, or governance choices. |
| Throughput | Count of work items completed during a defined period. |
| Transformation governance | Decision rights, standards, controls, evidence, and review routines used to direct enterprise change. |
| Work in progress | Work currently in active workflow states and not yet completed. |
| Write-back | Automated or manual action that changes source-system data based on external processing or decisions. |
