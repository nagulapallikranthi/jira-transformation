# Enterprise Jira Transformation Framework — Site Map

## Purpose

This site map defines the intended public information architecture for the Enterprise Jira Transformation Framework. It separates executive orientation, implementation guidance, analytics, reusable assets, and project governance so that different audiences can reach useful material quickly.

## Primary Navigation

| Section | Audience Need | Primary Content |
|---|---|---|
| Home | Understand the framework and choose a path | Executive proposition, featured resources, lifecycle, audience routes |
| Framework | Understand the transformation model | Principles, lifecycle, target operating model, decision quality |
| Analytics | Explore decision-ready reporting | Executive, sprint, JSM, transformation, and FinOps dashboards |
| Governance | Establish controls and ownership | Decision rights, standards, exceptions, auditability, review cadence |
| Playbooks | Plan and lead transformation work | Assessment, consolidation, migration planning, adoption, stabilization |
| Runbooks | Execute controlled operational procedures | Cutover, rollback, validation, reconciliation, operational readiness |
| Reference | Use standardized definitions and patterns | Metrics, templates, data policy, architecture, terminology |
| Roadmap | Understand maturity and planned expansion | Current release, upcoming capabilities, contribution priorities |

## Content Status Labels

Every major artifact should use one of the following labels:

- **Concept** — early design or proposed approach.
- **Draft** — usable content still under active review.
- **Reference** — reviewed and suitable for general use.
- **Template** — reusable structure requiring local adaptation.
- **Prototype** — functional demonstration using synthetic data.

## Navigation Standard

Every major document should include:

- a clear purpose statement;
- intended audience;
- links to prerequisite material;
- links to the next logical action;
- related metrics, playbooks, runbooks, or templates;
- a status label and last-reviewed date when formal release governance is introduced.
