# Security Policy

## Scope

This repository contains documentation, synthetic examples, static dashboard prototypes, and reusable templates. It must never contain real credentials, tokens, private URLs, customer data, employee data, tenant information, internal incident details, or proprietary configurations.

## Reporting a vulnerability or exposure

Do not open a public issue for suspected credential exposure, confidential data, or a security-sensitive defect.

Contact the repository owner privately through the email address listed on the maintainer's GitHub profile. Include:

- affected file, page, or commit;
- a concise description of the issue;
- potential impact;
- safe reproduction steps, when relevant;
- recommended remediation, when known.

Do not include live secrets or unnecessary personal data in the report.

## Response targets

The maintainer aims to acknowledge credible reports within five business days, assess severity, remove exposed material when necessary, and document non-sensitive remediation in the changelog.

## Supported versions

Security and confidentiality corrections apply to the current `main` branch and the latest published release. Historical releases may not receive non-critical updates.

## Safe-harbour intent

Good-faith security research that avoids privacy violations, service disruption, data destruction, and unauthorized access is welcomed. This statement does not grant permission to test third-party Jira, Atlassian, cloud, or customer systems.
