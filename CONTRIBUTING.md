# Contributing

Thank you for helping improve the Enterprise Jira Transformation Framework.

## Contribution principles

Contributions must be organization-neutral, evidence-based, reusable, and safe for public release. Do not submit employer, customer, employee, tenant, project, incident, credential, financial, security, or proprietary information.

## Before contributing

1. Read `PORTFOLIO_DATA_POLICY.md`.
2. Review `docs/Documentation-Standards.md`.
3. Search existing issues and pull requests.
4. Open an issue for substantial new content or structural changes.

## Content requirements

Every substantial contribution should explain:

- purpose and intended audience;
- scope and assumptions;
- inputs and dependencies;
- recommended approach and alternatives;
- controls, ownership, and decision rights;
- measurable outcomes and validation criteria;
- risks, trade-offs, and limitations.

Use synthetic examples only. Replace organization-specific names with generic placeholders.

## Branch and pull-request workflow

1. Create a focused branch.
2. Make one coherent change per pull request.
3. Update related navigation and cross-links.
4. Validate Markdown links, diagrams, examples, and dashboard behavior.
5. Complete the pull-request checklist.

## Documentation style

Use clear headings, short paragraphs, accessible language, and decision-oriented tables. Define acronyms on first use. Avoid unqualified claims and vendor marketing language.

## Technical examples

JQL, SQL, MDX, DAX, REST, automation, and code samples must include purpose, assumptions, required fields, expected output, limitations, and validation guidance. Never include real URLs, IDs, tokens, or credentials.

## Review standard

A contribution is ready when it is accurate, organization-neutral, internally consistent, cross-linked, usable by the intended audience, and free of confidential information.
