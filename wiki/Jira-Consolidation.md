# Jira Project Consolidation

## Purpose
- Standardize workflows, fields, and configurations across Jira projects
- Improve reporting and visibility
- Reduce redundancy and maintenance overhead

## Scope
- Define source and target projects
- Establish unified workflows and field mapping
- Align permissions and board configurations

## Pre-Consolidation Assessment
1. Inventory existing projects
2. Compare workflows, fields, and screens
3. Identify custom configurations
4. Document dashboard dependencies

## Standardization Blueprint
| Area | Standard Approach |
|---|---|
| Issue Types | Epic, Story, Task, Bug, Incident |
| Workflows | Reusable workflow schemes |
| Fields | Remove duplicates, adopt global contexts |
| Screens | Align screen schemes per issue type |
| Permissions | Role-based access with standardized groups |

## Execution Steps
1. Freeze configuration changes before consolidation
2. Clone or export project configurations
3. Apply standardized schemes to target project
4. Migrate issues to target project
5. Validate historical data links and references
6. Perform UAT and finalize rollout

## Testing and Validation Checklist
- Boards load with proper status column mapping
- Permissions reflect expected team access
- Dashboards display accurate data
- Filters run without errors

## Post-Consolidation Activities
- Train teams on new structures
- Update documentation and communication channels
- Archive old projects when confirmed stable
